# 파일 관리

이 저장소는 시장 전략을 쓰는 작업 공간이다. 기준 문서는 루트, 시장별 결과와 근거는 `전략서/`, 관리 방법과 점검 기록은 `관리/`에 둔다. 운영자가 분류·이름·목록을 매번 챙기지 않도록 작업하는 AI가 함께 갱신한다.

## 현재 구조

```text
README.md                         시작 안내
1-프로젝트지침.txt                  목적과 우선 원칙 / ChatGPT 지침
2-공략규약.md                      조사 방법과 전략서 양식
AGENTS.md / CLAUDE.md              로컬 도구 진입점
전략서/
  README.md                       전체 시장 목록
  <시장 이름>/
    전략서.md                      현재 전략 하나
    근거.md                        출처·확인 범위·자료 설명
    원자료-YYYY-MM-DD.csv           실제 표본이 있을 때만
관리/
  파일관리.md                      이 문서
  점검기록.md                      최근 전체 점검과 남은 한계
  check_repository.py             구조·연결·형식 확인
.claude/skills/market-attack/       Claude Code 명령 진입점
```

현재 전략은 [시장 목록](../전략서/README.md)에서 바로 연다. 시장 이름을 폴더에서 알 수 있으므로 파일명에 다시 반복하지 않는다. 사람이 자주 여는 자료를 더 깊은 하위 폴더로 나누지 않는다. 폴더는 실제 자료가 생길 때만 만든다.

## 만들고 고치는 법

1. 시장명으로 기존 폴더와 목록을 먼저 찾는다. 같은 시장은 현재 `전략서.md`를 고친다. `최종`, `최종2`, `수정본`, `v2` 같은 병렬 최신본을 만들지 않는다.
2. 전략서 맨 위의 작성일은 유지하고 수정일·상태·바꾼 이유를 갱신한다. 상태는 `실행 전 확인`, `운영 중`, `중단·보류` 중 실제 상황이다. 수익 자료가 없으면 문서가 완성되어도 실행 전 확인이다.
3. 수집 자료는 `원자료-YYYY-MM-DD.csv`에 둔다. 같은 날 다른 표본이면 `원자료-YYYY-MM-DD-<자료 종류>.csv`로 구분한다. 기존 표본을 새 수치로 덮지 않고 새 수집일 파일을 만든다. 허위 빈 CSV나 추정 원자료는 만들지 않는다.
4. `근거.md`에 출처 주소·실제 확인일·발표일/적용일·확인한 사실·한계를 적는다. 정책은 규약의 「공식 최신 규칙 확인」에 따라 적용 대상·예정 변경·전략에 반영한 점도 같은 파일에 남긴다. 별도 정책 목록을 중복 생성하지 않는다. CSV는 수집 방법·대상·조건·각 열·단위·빈칸 뜻·중복 가능성을 설명하고 링크한다. 과거 원문을 다시 안 열었다면 확인일을 바꾸지 않는다.
5. 전략과 근거·자료가 연결되면 전체 시장 목록의 주력·수정일·상태를 맞춘다. 경로 변경은 모든 참조도 함께 바꾼다. 중복 시장 폴더는 합치되 원본과 변경 이유를 보존한다.
6. 구조 검사와 내용 대조를 한다. 오류를 고친 뒤 필요한 결과만 기록한다. 단순 문구 수정 때마다 새 점검 보고서를 만들지 않는다.

새 시장명의 `/`, `\`, 제어문자와 `.`·`..` 같은 경로 이동 표현은 파일명에 넣지 않는다. 한글·띄어쓰기는 유지하며 셸에서는 경로를 따옴표로 감싼다. 링크는 상대 경로를 쓰고 공백은 `%20` 또는 `<경로>`로 표현한다.

## 자료를 남기는 기준

- 원자료에는 공개 상품·콘텐츠의 ID/주소, 관측 조건, 분석에 필요한 값만 남긴다. 작가·판매자·채널 운영자 이름, 이메일·전화번호·계정 비밀은 수집하지 않는다. 제목에 불필요한 개인 정보가 들어 있으면 비식별화하고 변경 범위를 기록한다.
- 원자료에 없던 ID·출처·날짜를 나중에 추정해 채우지 않는다. 결측과 “없음/0”을 구분한다. 공개 수치와 추정·계산 결과를 나눈다.
- 중복 행은 뜻을 확인하고 처리한다. 여러 검색 결과에 같은 상품이 나온 것일 수 있으므로 임의 삭제하거나 총행 수를 고유 상품 수로 쓰지 않는다.
- 원자료를 정정·비식별화할 때 변경 열·행 수·보존 여부를 `근거.md`에 남긴다. 이미 Git에 들어간 개인 정보는 현재 파일에서 지워도 과거 이력에 남는다. 이력 재작성·원격 변경은 별도 작업으로 판단한다.
- 길고 재사용하지 않을 HTML·JS·렌더·로그는 시스템 임시 폴더에서 다룬다. 판단에 필요한 원문 주소와 요약·확인 범위는 저장소에 남긴다. 재현에 꼭 필요한 작은 캡처는 해당 시장 폴더에 날짜와 내용을 드러내는 이름으로 보관하고 근거에서 링크한다.
- 실제로 운영 결과를 받으면 같은 시장에 `실적-YYYY-MM-DD.csv`를 만들 수 있다. 기간·통화·매출·차감·정산·작업 시간의 정의를 근거에 남긴다. 추정값을 실적이라고 쓰지 않는다.

## 이력과 정리

현재 전략은 한 파일, 이전 판단은 Git 이력으로 관리한다. 커밋·푸시는 요청받았을 때 하고 한국어 메시지를 쓴다. 커밋되지 않은 내용은 Git으로 복구할 수 있다고 가정하지 않는다. 큰 교체 전에 기존 변경을 확인하며, 손실 가능성이 있으면 복구 가능한 별도 보존본을 먼저 확보한다.

정리 때문에 가짜 날짜별 백업이나 빈 보관 폴더를 만들지 않는다. 버린 시장도 자료 가치가 있으면 현재 폴더에서 상태와 까닭을 바꿔 남긴다. 재생성 가능한 캐시·시스템 임시물은 지우고 `.gitignore`에 재유입 방지 패턴을 둔다. 사용자 원자료·미완 작업을 이름만 보고 삭제하지 않는다.

`.git`, 도구 설정 경로는 일반 문서처럼 옮기지 않는다. `CLAUDE.md`는 `AGENTS.md`를 참조하므로 같은 규칙을 복사해 두지 않는다. 공통 목적은 1번, 절차·양식은 2번, 저장 경로는 AGENTS와 이 문서가 담당한다. 요약 안내가 달라졌으면 원본 기준에 맞춰 고친다.

## 변경 후 확인

```sh
python3 관리/check_repository.py
```

이 검사는 읽기만 하며 추가 설치나 네트워크 연결이 없다. 시장 목록 누락, 로컬 링크 단절, 전략서 칸·카드 길이·상태·날짜 누락, 근거·CSV 연결, 금지한 개인정보 열, CSV 행 구조, 중복 파일을 찾는다. 경고와 오류를 모두 읽고 고친다.

**기계 검사는 전략의 옳음을 판정하지 않는다.** 작성자는 원래 요청과 카드·본문을 직접 비교해 AI 제작·자동화 전제, AI 경쟁에서도 남는 고객 가치, 고객 국가 선택, 주력, 돈 낼 사람, 첫 유입, 실제 비용과 반복 수고, 확장 조건, 가장 큰 미확인 전제가 일치하는지 확인한다. 칸 제목을 채웠다는 이유로 통과시키지 않는다. 결론을 바꾸는 정책·비용은 원문으로 확인하며, 실적이 없으면 수익 검증 전이라고 남긴다. 공통 전제가 바뀌었는데 기존 전략을 아직 재검토하지 않았으면 해당 전략 첫머리와 시장 목록에 범위를 표시하고, 과거 점검 통과를 새 전제의 충족으로 읽히게 두지 않는다.

ChatGPT에 옮길 때는 루트의 1번 지침과 2번 규약을 교체한다. 다른 시장 전략서는 공통 참고 자료로 한꺼번에 올리지 않는다. 같은 시장을 이어갈 때 그 시장의 현재 전략·필요한 근거만 제공한다. `관리/`는 로컬 관리용이며 추가 업로드가 필수는 아니다.

## 조사해서 채택한 기준

2026-10-20 원문을 확인하고 이 저장소 크기와 한국어 사용에 맞춰 적용했다.

| 원문 | 채택한 내용 | 적용 |
|---|---|---|
| [Smithsonian 파일·표 자료 관리](https://library.si.edu/research/best-practices-filenaming-organizing-and-working-data) | 뜻이 보이는 일관된 이름·폴더, 경로와 파일명의 불필요한 반복 줄이기 | 시장별 폴더 + `전략서.md`, 날짜가 있는 원자료. 원문의 영문·무공백 권고는 한국어 사용 편의에 맞게 그대로 따르지 않았다 |
| [Stanford 자료 설명](https://laneguides.stanford.edu/DataManagement/Documenting) | 프로젝트와 파일 각각의 맥락, 출처·열 정의·변경·검증 설명 | 루트 안내 + 시장별 `근거.md`와 자료 설명 |
| [Git의 gitignore 문서](https://git-scm.com/docs/gitignore) | 무시 규칙은 이미 추적 중인 파일을 제거하지 않는다 | 캐시 패턴 보완, 실제 추적·참조 확인 후 정리 |

시장별 분류는 결과·근거·표본을 함께 찾을 수 있어 채택했다. 날짜별 폴더에 전략을 흩어 놓는 방식, 하나의 폴더에 모든 시장의 자료를 쌓는 방식, 양식·목록을 여러 파일에 중복 관리하는 방식은 이 규모에서 유지 수고가 더 커 채택하지 않았다.
